Houston preprocessing (run from repo root, in order)
====================================================

1. Crop raw/ to one watershed -> houston/houston_<name>/ (6 gpkgs + region.shp)
   conda run -n hydrolib_env python houston/crop_to_watershed.py --list
   conda run -n hydrolib_env python houston/crop_to_watershed.py "WHITE OAK BAYOU"

2. Fill NULL/empty open_drains LINETYPE with "Offroad Channel - Manmade"
   (run BEFORE step 3 so the filled features land in open_drains_offroad)
   conda run -n hydrolib_env python houston/fill_open_drains_linetype.py houston/houston_white_oak_bayou --overwrite

3. Mark features into separate layers of Stormdrain.gpkg (re-run = layers rewritten)
   conda run -n hydrolib_env python houston/mark_stormdrain_features.py houston/houston_white_oak_bayou

4. Remove roadside discharge points, roadside/railroad ditch open_drains, and Virtual Junction/NULL network_structures
   (run AFTER step 3, it deletes the Railroad Ditch features step 3 marks;
    use --layers network_structures to only remove network_structures)
   conda run -n delft3d_dhydamo python houston/remove_stormdrain_features.py houston/houston_white_oak_bayou --overwrite

5. Remove gravity_mains_crossings with an endpoint on a manhole / inlet / fitting
   (default --tol 0.01 m absorbs the ~mm coordinate noise between pipe ends and nodes; --tol 0 = exact)
   conda run -n hydrolib_env python houston/remove_by_endpoint.py houston/houston_white_oak_bayou --overwrite

6. Remove gravity_mains_crossings whose BOTH endpoints join an open_drains_offroad endpoint
   conda run -n hydrolib_env python houston/remove_by_endpoint.py houston/houston_white_oak_bayou --nodes open_drains_offroad --require both --overwrite

Optional: remove source-layer features that match a mask layer
   (--match id|equals|intersects|within, default id on OBJECTID)
   conda run -n hydrolib_env python houston/remove_by_mask.py houston/houston_white_oak_bayou gravity_mains gravity_mains_crossings --overwrite
   conda run -n hydrolib_env python houston/remove_by_mask.py houston/houston_white_oak_bayou open_drains open_drains_roadside --overwrite

7. Connect outfall pipes to off-road channels (snap / trim overshoot / perpendicular extension)
   (targets: pipes ending on an Outfall discharge point or Drain Node fitting, or PIPETYPE=Outfall;
    --snap-dist 2 m, --max-dist 20 m; channels are split at every connection; QA layer outfall_connections;
    --network-outlets: also connect pipe networks without any trigger that still reach no channel, at their
    dead-end outlet nearest to a channel -- 24 networks / 226 pipes in White Oak Bayou;
    extensions that would cross another line are skipped (status extend_crosses; --allow-crossing to force).
    Large --max-dist creates long artificial pipes: at 110 m, 87 extensions would cross other lines)
   conda run -n hydrolib_env python houston/connect_outfalls_to_channels.py houston/houston_white_oak_bayou --dry-run
   conda run -n hydrolib_env python houston/connect_outfalls_to_channels.py houston/houston_white_oak_bayou --network-outlets --overwrite

7b. Convert too-far outfall discharge_points to inlets & normalise inlets/manholes
   (run AFTER step 7 --overwrite; reads outfall_connections QA layer;
    discharge_points Outfall at the outfall-end of a too_far pipe + orphan outfalls
    are converted to inlets: DEPTH=3 m (9.84252 ft), RIMELEV=DEM(m)*3.28084,
    INVERTELEV=RIMELEV-DEPTH; removed from discharge_points + discharge_points_outfall;
    in the same run, existing inlets and manholes with DEPTH NULL/non-numeric/<=0 are repaired
    to DEPTH=3 m. Positive existing DEPTH values are kept unchanged. For a repaired
    node, the script uses existing RIMELEV (>0) first, then INVERTELEV (>0), then DEM, then
    the explicit fallback RIMELEV=0 ft / INVERTELEV=-9.84252 ft;
    QA layer: converted_outfalls; --revert undoes converted outfalls only and does
    not restore the normalised attributes of pre-existing inlets/manholes)
   conda run -n delft3d_dhydamo python houston/outfalls_to_inlets.py houston/houston_white_oak_bayou --dry-run
   conda run -n delft3d_dhydamo python houston/outfalls_to_inlets.py houston/houston_white_oak_bayou --overwrite
   # Để hoàn tác bước này:
   # conda run -n delft3d_dhydamo python houston/outfalls_to_inlets.py houston/houston_white_oak_bayou --revert

8. T-junctions between open_drains / gravity_mains (endpoint of one line on the middle of another)
   (run LAST, after all removals and step 7; --action mark (DEFAULT) = t_junctions point layer only, NOTHING is cut,
    even with --overwrite; split = cut host lines so 3 branches share the node, both = split + mark;
    --snap-dist D: also dangling ends stopping up to D m short of a line (look like a T, but no contact);
    0.5 m -> ~100 extra junctions in White Oak Bayou; review with --action mark first, kind=near)
   conda run -n hydrolib_env python houston/fix_t_junctions.py houston/houston_white_oak_bayou --snap-dist 0.5
   conda run -n hydrolib_env python houston/fix_t_junctions.py houston/houston_white_oak_bayou --action both --snap-dist 0.5 --overwrite

9. Remove standalone manholes / inlets / fittings / discharge_points that touch no open_drains / gravity_mains
   (run AFTER steps 7, 7b and 8; connected = within --tol 0.01 m of a branch ANYWHERE along it, not just its ends --
    many inlets / discharge points sit mid-pipe or mid-channel; --ends-only for the strict endpoint test;
    discharge_points_outfall is cleaned by OBJECTID too; removed nodes -> QA layer standalone_nodes)
   conda run -n hydrolib_env python houston/remove_standalone_nodes.py houston/houston_white_oak_bayou --dry-run
   conda run -n hydrolib_env python houston/remove_standalone_nodes.py houston/houston_white_oak_bayou --overwrite

10. Fill NULL/empty/0 attributes of gravity_mains / open_drains (only those cells; --keep-zero leaves 0 values alone)
   (OBJECTID: NULL + duplicates (split pieces) renumbered, first fid keeps its id -> run AFTER steps 7/8;
    gravity_mains: UPELEV/DOWNELEV = INVERTELEV of inlet/manhole on start/end point (--tol 0.01 m),
    else lowest known elevation of the connected pipe ends at that point, else INVERTELEV of an
    inlet/manhole along the pipe, else the bed (DEM) of the open_drain the end lies on, else the
    pipe's own other end (level pipe); HEIGHT = WIDTH for BOX,
    discharge_points FLOWELEV = bed (DEM) of nearest open_drains + DEPTH/3 (after channels are filled),
    PIPETYPE=Collector, MAINSHAPE=RND, WIDTH=78.74 in (2 m; replaces the 6.56 ft of an earlier run), MATERIAL=RCP;
    open_drains: WIDTH/BANKWIDTH (ft) from hcfcd_contours crossings on transects every 25 m,
    DEPTH = DEM at bank crossings - DEM bed; BANKWIDTH<WIDTH -> both refilled from the contours;
    rest (no contour result) -> WIDTH 4 m / BANKWIDTH 10 m (in ft), DEPTH from DEM (else 1.5 m);
    ends with a NULL/empty/0 check of all fields read back from the written gpkg;
    BED/SIDEMATERIAL = EAR/EAR (Natural), EAR/CP (Manmade);
    QA layer channel_transects)
   conda run -n hydrolib_env python houston/fill_null_attributes.py houston/houston_white_oak_bayou_v4_cleaned --dry-run
   conda run -n hydrolib_env python houston/fill_null_attributes.py houston/houston_white_oak_bayou_v4_cleaned --overwrite

Check (run AFTER steps 7 and 8, they rewrite the layers): connectivity from a reference branch
   (DFS over gravity_mains + open_drains sharing an endpoint; mark layer connected_network, rewritten each run;
    --t-junctions also follows endpoint-on-interior contacts; near misses up to --gap-dist 1 m are printed;
    raise --tol to bridge real gaps. Prefer --ref-objectid: fids are renumbered by every rewrite)
   conda run -n hydrolib_env python houston/check_connectivity.py houston/houston_white_oak_bayou --ref-layer open_drains --ref-objectid 197064

Depth level of the drainage tree below a reference branch (for planning subregions)
   (BFS tree from the reference over gravity_mains + open_drains, shared endpoints within --tol 0.01 m;
    level = branching level (0 = main stem, +1 per side branch; the stem follows the largest upstream network,
    same layer preferred), hop_depth = branches from the reference, trib_id = level-1 tributary system,
    upstream_len; RGB colours in level_rgb / hop_rgb; mark layer branch_depth + QGIS styles 'branch level'
    (default) / 'hop depth' in layer_styles; PNG map <dir>/branch_depth.png)
   conda run -n hydrolib_env python houston/branch_depth.py houston/houston_white_oak_bayou_v3_cleaned --ref-layer open_drains --ref-objectid 197064
   With breaks: --cut LAYER:OBJECTID (repeatable) = branch is reached but not passed; output -> branch_depth_cut.
   The network has loops, so a single cut is often bypassed: the script then prints the minimum extra
   --cut set (pipes preferred) that really cuts off what lies beyond. E.g. 58784 alone cuts off nothing;
   it is bypassed by a sewer trunk (Outfall 167706) and a box culvert (291259):
   conda run -n hydrolib_env python houston/branch_depth.py houston/houston_white_oak_bayou_v3_cleaned --cut open_drains:58784 --cut gravity_mains:167706 --cut gravity_mains:291259

Notes
- Fill / remove / split / connect scripts (2, 4, 5, 6, 7, 8 split, mask): without --overwrite they copy the folder to <dir>_cleaned;
  --dry-run only prints counts.
- Steps 7 and 8 do not touch mark layers (gravity_mains_crossings, open_drains_*); split pieces keep their host's OBJECTID.
- Steps 7 and 8 rewrite open_drains / gravity_mains and renumber ALL fids: fid columns of layers written before
  (connected_network, t_junctions, outfall_connections) then point at other features (a warning lists them).
  t_junctions written by step 8 --action both has split=1: those junctions were resolved; its fids are pre-split.
- Close the QGIS project before --overwrite (Stormdrain.gpkg is locked while open).
- Re-running step 3 rebuilds gravity_mains_crossings, so re-run steps 5 and 6 after it.

có 2 cách để kết nối outfall đến kênh mương:
(1) chỉnh vị trí endpoint của các nhánh gravity_mains sao cho endpoint được nối với 1 khớp node trong linestring của nhánh. với cách này, vị trí chỉnh endpoint không nên quá xa vị trí ban đầu, và chỉ nên dùng cách này khi endpoint gần khớp node của kênh mương, hoặc là nhánh gravity_mains đó đang bị kéo dài đến mức mà cắt qua (crossing) kênh mương.
(2) từ endpoint của nhánh gravity_mains gần kênh mương nhất hoặc tại 1 discharge points, kéo dài branch chứa điểm này bằng cách vẽ thêm 1 đoạn line segment của branch (vẫn thuộc branch đó). đoạn nối thêm vuông góc với đoạn line segment của branch  gần nhất tại điểm đó, và 1 endpoint của đoạn này phải nằm trên kênh mương (điều này có thể tạo ra T-junctions, do đó cần xử lý như script trước)

các đối tượng sau cần xét đến để áp dụng 2 cách kia:
- các nhánh gravity_mains có 1 endpoint trùng vị trí chính xác với node discharge_point có DISCHRGTYP=Outfall hoặc node fitting có FITTINGTYPE=Drain Node
- các nhánh gravity_mains có PIPETYPE=Outfall
