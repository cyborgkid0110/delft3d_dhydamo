# Calibrating the WOB D-Flow FM submodels in Delft-FEWS

This is how to set up the calibration workflow (part 8 of
`G:\VTS\IoT_Solutions\deflt3d\Delft-FEWS_Hieu_chinh_mo_hinh.md`) for the WOB submodels
that already run in the FEWS 2023.02 demo (`G:\Deltares\Delft_FEWS_demo\Application`,
installed with `houston/fews/build_fews_package.py`, see `houston/fews/README.md`).
It uses the measured data in `houston/raw/usgs` and `houston/raw/precip`.

All config is generated by `build_fews_calibration.py` and is schema-checked against the
XSDs of the installed FEWS. The model side (parameter writing, observation points, MPI
run, his → PI) was run outside FEWS on sub1 (§9). FEWS has not yet run it itself.

## 1. What the data allows: read this first

| Gauge (USGS) | Submodel | Data Oct 2025 – Oct 2026 | Basin in sub1 / sub2 / outside |
|---|---|---|---|
| 08074200 Brickhouse Gully at Clarblak | **sub1** | **none**: discontinued 1983 (only annual peaks 1965–1983) | – |
| 08074250 Brickhouse Gully at Costa Rica St | sub2 | stage 5 min (continuous), Q only above ~200 cfs (5.7 m³/s) | **51 % / 41 % / 7 %** |
| 08074150 Cole Ck at Deihl Rd | sub2 | stage 15 min, Q only above ~200 cfs | 25 % / 48 % / 24 % |
| 08074020, 08074500, 08074598, 08074540 | sub3 / sub5 | yes | mostly outside sub1–sub5 |

The basin shares come from the USGS NLDI upstream basin of each gauge, intersected with
the submodels' `2D_extent.shp`. Both gauges have gage datum 0.0 ft NAVD88, so the
stage is an elevation (ft × 0.3048 = m NAVD88, the model datum).

What follows from this:

1. **sub1 cannot be calibrated against measurements.** Its only gauge is dead, and
   sub1's runoff is measured only further down, at 08074250 in sub2.
2. **sub2 alone cannot be calibrated either.** Half of the 08074250 basin lies in sub1, and
   sub1 and sub2 are not connected (the links between submodels were not built). Manning
   values fitted on sub2 alone would only make up for the missing sub1 water.
3. **The real calibration target is 08074250 on a sub1+sub2 model** (§8). 08074150 can
   serve as a check only: a quarter of its basin is outside every submodel.
4. On sub1, the installed model, use the chain for a **twin experiment** (§6). It tests
   the whole FEWS setup (modifier → model → import → statistics → auto-calibration) and
   shows which parameters the outlet discharge is sensitive to.

## 2. How the calibration chain works

```
IFD node "WOB sub1 1D2D calibration" (local run)   ◄─ modifier "sub1 Manning roughness"
  │                                                     (edit by hand, or AC + Auto calibrate)
  workflow WOB_sub1_Calibration
  ├─ ImportCalibration_WOB_sub1   Import/Calibration_WOB_sub1/*.xml → QR.obs, HG.obs (gauges), PC.obs (rain)
  ├─ WOB_sub1_Calibration (General Adapter, folder Modules/WOB_sub1/calibration)
  │    exportState      cold state at T0 − 24 h (always cold: no warm state from other Manning values)
  │    exportTimeSeries PC.obs → input/fm_forcing.xml            (boundaries keep the model's 0.1 m)
  │    exportDataSet    WOB_sub1_Calibration.zip → dimr_model    (= installed model + ObsFile/CrsFile)
  │    exportParameter  ModuleParFiles/WOB_sub1_Calibration.xml + modifier → input/params.xml
  │    exportRunFile    input/pi-run.xml (param.<ID> = where each value goes)
  │    ▸ bin_adapter/fews_apply_parameters.py  params.xml → roughness_*.ini, structures.ini, all MDUs
  │    ▸ bin_adapter/fews_dimr_preadapter.py   run period, rain, cold start (the existing pre-adapter)
  │    ▸ dimr_bin/bin/run_dimr_parallel.bat 16 dimr_config_parallel.xml
  │    ▸ bin_adapter/fews_his_to_pi.py         DFM_0000_his.nc → fews_his.xml
  │    importTimeSeries fews_his.xml → QR.sim, HG.sim (15 min) at the gauges
  └─ WOB_sub1_Calibration_PI (Performance Indicator)  NSE, BIAS, MAE, VOL for QR and HG per gauge
```

Changes from the design in part 8 of the note, found while building it against the real model:

| Part 8 | Here | Why |
|---|---|---|
| `patch_model.py` also renames `frictionId` to `Manning_<value>` | `frictionId` is kept, only `frictionValue` changes | `crsdef.ini` refers to `Manning_0.013` etc.: renaming it breaks the link from every cross-section to its roughness |
| patches `DFM.mdu` only | `unifFrictCoef` set in `DFM.mdu` **and** `DFM_0000…0015.mdu` | the MPI run reads the partition MDUs |
| pipes through `roughness_*.ini` only | pipe parameters also set `bedFriction` of the culverts with the same value (3,364 + 65 in sub1) | most of the storm drain network is culverts (`DU_`), whose friction is in `structures.ini` |
| 4 parameters by file number | parameters by `frictionId`, derived per submodel | file numbers differ between submodels (sub2 has 5 files, another order, plus 0.01) |
| `importNetcdfActivity` on `*_his.nc` | `fews_his_to_pi.py` + PI import | the model had no observation points; PI import is the documented, robust path |
| `DimrPreAdapter` (`fews-dimr-adapter-bin`) | the existing `fews_dimr_preadapter.py` | the Deltares adapter isn't in the demo |
| boundaries from FEWS | not exported | the pre-adapter stops on an exported series without values; the model's 0.1 m free-outfall levels stay |

## 3. Calibration parameters (sub1)

Derived from the model by the builder. min/max are the bounds that the **AC** button
proposes. They are generous, so narrow them in the panel if you have field knowledge.

| Parameter | Now | min – max | Goes to | What it is |
|---|---|---|---|---|
| `MANNING_PIPE_013` | 0.013 | 0.009 – 0.021 | `frictionId Manning_0.013` + 3,364 culverts | concrete pipes and boxes (3,416 sections) |
| `MANNING_PIPE_024` | 0.024 | 0.017 – 0.038 | `Manning_0.024` + 65 culverts | corrugated pipes (79 sections) |
| `MANNING_CHANNEL_03` | 0.03 | 0.018 – 0.075 | `Manning_0.03` | open channels, trapezium/zw (124 sections) |
| `MANNING_CHANNEL_025` | 0.025 | 0.015 – 0.062 | `Manning_0.025` | lined channels (7 sections) |
| `MANNING_2D` | 0.023 | 0.015 – 0.20 | `unifFrictCoef` in all MDUs | uniform 2D overland Manning |

For the twin experiment and the first real attempts, calibrate **MANNING_CHANNEL_03,
MANNING_2D and MANNING_PIPE_013** and keep the others fixed. They are short, few, and
hardly affect a gauge on the main channel. Fewer parameters also means far fewer model runs (§7).

## 4. Build the package

```bat
cd /d G:\workspace\github\delft3d_dhydamo\houston\fews\calibration
G:\miniforge3\envs\hydrolib_env\python.exe build_fews_calibration.py --submodel sub1 ^
  --gauge "WOB_sub1_G01=R_92665:282:Brickhouse Gully at Clarblak (virtual, ex USGS 08074200)" ^
  --gauge "WOB_sub1_G02=R_230894:300:Brickhouse Gully at the sub1 outlet (virtual)" ^
  --gauge "WOB_sub1_G03=R_230849:300:Brickhouse Gully at the sub1-sub2 hand-over (virtual)" ^
  --target WOB_sub1_G02 --run-hours 24 --mdu dtUser=900 --mdu dtMax=900 ^
  --event 2026-03-07T10:00/2026-03-08T10:00 ^
  --event 2026-04-18T06:00/2026-04-19T06:00 ^
  --event 2025-11-29T17:00/2025-11-30T17:00
```

* `--gauge ID=BRANCH:CHAINAGE[:NAME]` puts a 1D observation point (water level) and an
  observation cross-section (discharge) at that spot. Find branch ids in QGIS, or
  through the FEWS map layer *sub1 1D branches* (tooltip). Ids starting with `USGS_` get
  their observations from `raw/usgs`.
* `--event START/END` (UTC) writes PI files for the import: MRMS rain averaged over the
  submodel's 2D extent, plus the USGS series for `USGS_` gauges. Each window should be
  `--run-hours` long and end at the T0 you'll use.
* `--mdu` is passed to the pre-adapter, the same as for the operational run.
* The builder reads the installed `WOB_sub1_Historical.zip` (so install sub1 first) and the
  live region files, and writes `package_sub1_calibration/Application`. Rebuilding
  replaces its own entries, so re-installing is safe.

The individual tools, if you want to make data by hand:

```bat
python fews_calibration_data.py usgs --site 08074250 --start 2026-03-07T10:00 --end 2026-03-08T10:00 -o usgs.xml
python fews_calibration_data.py rain --polygon ...\sub1\2D_extent.shp --location WOB_sub1_rain --start ... --end ... -o rain.xml
python fews_calibration_data.py twin --his DFM_0000_his.nc --map WOB_sub1_G02=WOB_sub1_G02 -o twin.xml
```

1. Close FEWS. Back up `Application\Config` (e.g. to `Config_backup_<date>`).
2. Copy the package over the application:
   ```bat
   robocopy G:\workspace\github\delft3d_dhydamo\houston\fews\calibration\package_sub1_calibration\Application G:\Deltares\Delft_FEWS_demo\Application /E
   ```

   * the filter *Houston WOB sub1 - calibration (obs / sim)* in the Data Viewer.

## 6. Use it

### 6.1 First run: test the chain (no modifier)

1. Set the system time: double-click the clock in the status bar → **T0 = 2026-03-08 10:00 GMT**.
   The demo shows GMT+02:00, so that's 12:00 on screen.
2. Select the node *WOB sub1 1D2D calibration* and press **Run** (local run). The node
   does not auto-run (`enableAutoRun = false`).
3. Follow progress in **System Monitor ▸ Running Forecasts** (D-Flow FM Complete %) and in
   `Modules\WOB_sub1\calibration\logs\dimr_console.txt`. The log panel shows the lines of
   both Python steps, e.g. `MANNING_CHANNEL_03 = 0.03 -> frictionValue of Manning_0.03`.
4. Check:
   * `calibration\input\params.xml`: the parameter values FEWS exported;
   * `calibration\dimr_model\dflowfm\roughness_*.ini`, `structures.ini`, `DFM_00*.mdu`: the
     values written; `ObsFile`/`CrsFile` present; `tStart`/`tStop` = T0 − 24 h … T0;
   * `calibration\dimr_model\dflowfm\output\fews_his.xml`: `waterlevel` and
     `cross_section_discharge` per gauge;
   * the node's display (or the filter): rain bars, QR.sim and HG.sim at G01–G03;
   * the statistics `NSE.QR`, … at T0 (they need QR.obs, so they appear after §6.2).

### 6.2 Twin experiment on sub1

This checks that the calibration can recover values it knows.

1. **Reference run**: run the node once with the default values (§6.1). Then turn its
   result into "observations":
   ```bat
   G:\miniforge3\envs\hydrolib_env\python.exe G:\workspace\github\delft3d_dhydamo\houston\fews\calibration\fews_calibration_data.py twin ^
     --his G:\Deltares\Delft_FEWS_demo\Application\Modules\WOB_sub1\calibration\dimr_model\dflowfm\output\DFM_0000_his.nc ^
     --map WOB_sub1_G01=WOB_sub1_G01 --map WOB_sub1_G02=WOB_sub1_G02 --map WOB_sub1_G03=WOB_sub1_G03 ^
     -o G:\Deltares\Delft_FEWS_demo\Application\Import\Calibration_WOB_sub1\twin_T0_20260308T10.xml
   ```
   The next run imports it as `QR.obs`/`HG.obs`. Only use twin files when no real
   observations exist for the same location; for G01–G03 there are none.
2. **Disturb**: open the modifiers (wrench icon / Ctrl+M) → new modifier *sub1 Manning
   roughness* → set e.g. `MANNING_CHANNEL_03 = 0.05`, `MANNING_2D = 0.06` → **Apply**.
   A local modifier is red and only exists in your client.
3. Run again. QR.sim now deviates from QR.obs, and `NSE.QR` drops below 1.
4. **Calibrate back** by hand (change values, Apply, re-run) or automatically (§6.4). The
   best values should come back near 0.03 / 0.023. A parameter that comes back anywhere
   with the same RMSE has no influence on this gauge; fix it in the real calibration.

### 6.3 Manual calibration (works now)

1. Node selected, open the modifiers, choose *sub1 Manning roughness*, set values, **Apply**.
2. **Run** (local). Compare QR.obs/QR.sim and HG.obs/HG.sim in the display, and look at
   `NSE.QR`, `BIAS.QR`, `VOL.QR` (volume error %) in the filter, at T0.
3. Change one parameter group at a time, e.g. first `MANNING_CHANNEL_03` for peak timing
   and height at the channel gauge, then `MANNING_2D` for the rising limb and volume
   reaching the network, then `MANNING_PIPE_013`.
4. Repeat for every calibration event (§1): change T0 to the event end, keep the modifier
   (`defaultValidTime` = valid for every T0), run. Judge the parameter set on all
   calibration events together, then run the validation events unchanged.
5. Write down the accepted set. FEWS only *exports* parameters, so the values have to
   go into the model itself afterwards (§6.5).

Local runs vanish when FEWS restarts. To keep one, use **Save local run**
(`saveLocalRunEnabled = true`).

### 6.4 Automatic calibration (needs OpenDA)

The configuration is ready (`calibrationObservationTimeSeries` = `QR.obs` and
`calibrationSimulationTimeSeries` = `QR.sim` at `--target`). The demo has **no OpenDA**,
though: `Modules\OpenDA` and an OpenDA jar are missing.

1. Get `OpenDA_bin.zip` for FEWS 2023.02 from Delft-FEWS support (fews-pm@deltares.nl /
   support). Unzip it into `Application\Modules\OpenDA` (binaries in `Modules\OpenDA\bin`).
2. In the modifier panel (*multiple module parameter modifiers*), press **AC** on each
   column to calibrate (e.g. `MANNING_CHANNEL_03`, `MANNING_2D`, `MANNING_PIPE_013`) and
   check the bounds.
3. **Auto calibrate**: choose the workflow start (T0 = event end) and the period to
   compare (the event window), and the SCE settings. *Maximum number of evaluations*
   must exceed `complexes × (2p + 1)`. With p = 3 and 2 complexes that is > 14; use ≥ 30.
4. Results: `Modules\OpenDA\runDir\RMSE_iterations.csv` (RMSE and parameters per run; the
   last line, `-1`, is the best). **Promote** saves a good run.

The objective is RMSE of one series pair (one gauge, one event per session). The run
budget in §7 limits what is realistic.

### 6.5 Put the result into the operational model

Write the accepted values into the model the operational workflow uses:
* in the model folder (`houston_white_oak_bayou_v5_cleaned/submodels/<sub>/delft3d_model/dflowfm`):
  `frictionValue` in `roughness_*.ini`, `bedFriction` of the matching culverts in
  `structures.ini`, `unifFrictCoef` in `DFM.mdu` and every `DFM_00NN.mdu`. The quickest
  way is to run `fews_apply_parameters.py` on a pi-run/params pair, as in §9;
* then rebuild and install the operational package (`build_fews_package.py`, README step 3–4)
  and the calibration package (so the next calibration starts from the new values).

## 7. Run time and budget

Measured on this PC (sub1, 16 MPI processes, OMP 1, `dtUser = dtMax = 900`, MRMS rain of
2026-03-08): **1,159 s wall time for 1.5 h simulated** (23:00–00:30, the start of the
36 mm/h hour; mean time step 1.23 s), so about 13 min per storm hour. Dry hours run
faster, but that wasn't measured: estimate **1–3 h per 24 h event run** and time your
first run. A sub1+sub2 model has about 1.8 M 2D cells (sub1 0.68 M + sub2 1.09 M), so
expect roughly 2.5× sub1.

| Approach | Model runs | Realistic? |
|---|---|---|
| manual, 3 parameters, 3 calibration + 4 validation events | 20–40 | yes |
| SCE, 3 parameters, 2 complexes, ≥ 30 evaluations, 1 event | 30–60 | yes, overnight / over a weekend |
| SCE, 5 parameters, 5 complexes (> 55 evaluations) | 60–150 per event | only with a short window or a coarser model |

Shorten runs by setting T0 to the end of the Q segment (Q above 200 cfs) and choosing
`--run-hours` just long enough to cover the rain plus 2–3 h of spin-up.

## 8. Real calibration against USGS 08074250 (sub1 + sub2)

**Option A, recommended: a merged sub1+sub2 submodel.** Build it with the existing chain:
1. Make a data folder next to the dataset, e.g. `houston_white_oak_bayou_v5_cleaned_sub12`,
   holding a copy of `output/` and a `wob_regions.gpkg` with **one** layer
   `white_oak_sub1` = union of the `white_oak_sub1` and `white_oak_sub2` polygons.
   `split_wob_submodels.py` reads every `white_oak_sub<k>` layer and gives each feature
   to the first ROI that contains it, so a 6th ROI in the original gpkg would stay empty.
2. `python tool/scripts/split_wob_submodels.py --data <that folder>`. Its `submodels/sub1`
   is the merged model. Build the mesh, model and MPI partitions as for v5 (mesh build,
   `notebook/houston_wob_build.ipynb`, partition). Lines crossing the sub1/sub2 border are
   whole features, so the network is connected again.
3. Install it in FEWS as an operational submodel (`build_fews_package.py --submodel sub12
   --mpi …`, after placing it under `submodels/sub12`), then build the calibration package:
   ```bat
   python build_fews_calibration.py --submodel sub12 ^
     --gauge "USGS_08074250=R_231237:346:Brickhouse Gully at Costa Rica St" ^
     --gauge "USGS_08074150=R_230867:76:Cole Ck at Deihl Rd" ^
     --target USGS_08074250 --run-hours 24 --mdu dtUser=900 --mdu dtMax=900 ^
     --event 2026-03-07T10:00/2026-03-08T10:00 --event 2025-11-29T17:00/2025-11-30T17:00 ^
     --event 2026-04-18T06:00/2026-04-19T06:00 --event 2026-05-23T07:00/2026-05-24T07:00 ^
     --event 2025-11-30T23:00/2025-12-01T23:00 --event 2026-03-11T02:00/2026-03-12T02:00
   ```
   (The branch ids are from sub2. Check them in the merged network, because the build can renumber.)
4. Calibrate as in §6.3/§6.4 on QR at `USGS_08074250` (Q > 200 cfs only), and check HG
   (stage) peaks and timing. HG at low flow is not comparable: the model starts dry and has
   no base flow, while the real channel always carries some.

**Option B: chain sub1 → sub2 without rebuilding.** sub2 overlaps the last ~2 km of
sub1's Brickhouse Gully, and its upstream channel boundary `937984.201890_4225620.392452`
sits where sub1 has gauge `WOB_sub1_G03` (R_230849, 300 m). Change that sub2 boundary from
`waterlevelbnd` to `dischargebnd` (`bnd.ext` + `boundaryconditions.bc`), feed it with
sub1's `QR.sim` at `WOB_sub1_G03`, and run sub1 then sub2 in one workflow. This misses the
storm pipes that cross the border, takes two runs per evaluation, and needs the
`WOB_sub2` FEWS install first. Use it only if the merged mesh is too expensive.

## 9. What was verified

* All generated XML (the config files plus the PI parameter and time-series files) validates against
  the XSDs in `bin\Delft_FEWS_schemas.jar` (FEWS 2023.02). A deliberately mis-ordered
  topology node is rejected, so the check works.
* The GA steps were run outside FEWS on sub1 with the package's own model zip and config
  properties: changed Manning values went into exactly the right lines (2 `frictionValue`
  lines, 3,429 culvert `bedFriction` lines, `unifFrictCoef` in 17 MDUs, nothing else). A
  0.013 → 0.024 change does not also catch the original 0.024 culverts. The pre-adapter
  set the period and rain. DIMR then ran on 16 MPI processes (exit 0, *Computation
  finished*). The 1D observation points/cross-sections (branchId + chainage) work in the
  partitioned run, and `DFM_0000_his.nc` holds all gauges. `fews_his_to_pi.py` gives
  `waterlevel` and `cross_section_discharge` per gauge, with the ids of the import IdMap.
  The his PI, USGS PI, MRMS rain PI, twin PI and params files all validate against the
  PI XSDs.
* **Look at this in your first full run:** after 1.5 h and ~20 mm of rain from a dry cold
  start, Q at the sub1 outlet (G02) was only 0.19 m³/s, and the level rose 0.17 m. The
  measured flow at 08074250 reached ~90 m³/s at 01:25. If the full 24 h run stays an
  order of magnitude low, the runoff path (street inlets, 1D2D links, dry storage) is the
  problem, not Manning. Roughness calibration cannot fix that, so check it first.
* Not verified: FEWS itself running the workflow, the modifier panel, the PI module output,
  and Auto calibrate (no OpenDA in the demo).

## 10. Limits

* One observation/simulation pair per auto-calibration configuration, RMSE only, one event
  per session (FEWS + OpenDA). Multi-event and multi-gauge judgement is manual (NSE/BIAS/VOL).
* Q at 08074250 is published only above ~200 cfs: the calibration sees peaks and recessions,
  not low flow. There is no base flow in the model, and the boundaries are free outfalls.
* MRMS rain is used as a spatial mean over the 2D extent (the model rain is uniform).
  Areal rain differences inside the 30 km² basin are lost; this limits how well any roughness fits.
* Only Manning values are calibrated. Infiltration, storage, inlet capacity and the 1D2D
  links matter for urban runoff too, but the model has no infiltration, so it isn't offered.
